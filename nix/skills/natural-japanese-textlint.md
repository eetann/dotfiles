## 付録A. textlint によるAI語彙検出（この環境の追加工程・省略しない）

この環境には `textlint-rule-preset-ai-words-ja` を組み込んだ textlint が入っている。§3 の静的検知では `scripts/lint.py` に加えて必ずこれも走らせる。

```
textlint-ai-ja <file>
```

形態素解析で、AIが多用する語（「効く」「踏み込む」「照合」「実測」「核心」「土台」など約50語）を指摘する。`lint.py` の禁止語リストとは辞書が重ならないため、片方だけでは取りこぼす。JSONで受け取るなら `--format json`、標準入力から読ませるなら `--stdin --stdin-filename doc.md` を足す。プリセットの有効化はコマンド側に埋め込んであるので、対象プロジェクトに `.textlintrc` は要らないし、作ってもいけない。

指摘が1件でもあると exit code は 1 になる。これは失敗ではなく「指摘あり」の意味なので、コマンドが落ちたと解釈しない。

出力は「別の表現に言い換えられないか検討してください」という提案であって、全置換の指示ではない。§4 と同じく finding を判断テーブルへ一行ずつ起こし、文脈に照らして「直す/残す（理由）」を仕分ける。固有名詞・引用・その語でしか指せない専門用語は残してよい。§5 の収束ループで `lint.py` を回し直すときは、textlint も同じタイミングで回す。

score モード（診断のみ）では `references/diagnose.md` のスコア算出式を変えない。textlint の指摘はスコアへ加算せず、補足の所見として件数と代表例を併記する。
